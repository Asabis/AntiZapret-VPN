# Persistent DNS/RPZ allowlist (GP-01)

This is part of the universal AZRelay/AntiZapret platform, **not** a TP-Link-only fix.

## Incident / cause

The live AntiZapret resolver returned 0.0.0.0 for ipify.org and
whatismyipaddress.com despite having these domains in
config/exclude-adblock-hosts.txt. This is because the generator appends
download/*deny-rpz.txt and config/*deny-rpz.txt **after** adblock overrides.
Explicit CNAME . records continued to deny those names.

## New permanent mechanism

Add ASCII/Punycode domain names, one per line, to:

    /root/antizapret/config/exclude-deny-hosts.txt

Example:

    ipify.org
    whatismyipaddress.com

The new rpz_allowlist.py build step runs on the generated AntiZapret deny.rpz
*before publication*. It removes exact rules for those names and rules for
their wildcard/subdomains from **every deny source**, including adblock,
explicit deny, and autogenerated rpz-passthru exceptions. Removing passthru
is intentional: Knot Resolver must continue to later proxy.rpz so the
selected domain can receive a Fake IP for selective routing.

This allowlist applies **only** to AntiZapret's deny.rpz (selective VPN),
not to deny2.rpz (full VPN). It does not automatically route domains:
add the same names separately to config/include-hosts.txt if they should
egress through the VPN, or leave them out if ordinary routing is preferred.

The parser fails before publishing when a broader parent wildcard deny
would still match an allowed child (for example, allowing api.example.com
while *.example.com is denied). Do not silently remove broad parent rules:
review the intended security policy instead.

## Scheduled update provenance (release gate)

The upstream `update.sh` downloads both `update.sh` and `parse.sh` on
each scheduled `doall.sh` run. If those URLs point to `GubernievS`, the
GP-01 parser hook can be overwritten during the daily update, silently
reintroducing blocked domains. This fork pins both script URLs to
`Asabis/AntiZapret-VPN/main` to preserve its allowlist integration.
Downloaded domain/IP and deny-source lists still use the upstream.

**Production is not automatically changed by this repository commit.**
Before enabling unattended updates, back up actual DE scripts, compare local
customizations, deploy the fork `update.sh` and `parse.sh` from one
reviewed commit, run two consecutive update+parse cycles under an exclusive
lock, verify the RPZ allowlist and confirm no unexpected side effects.
Any newly fetched parser must be verified after the update. Coordinate all
`parse.sh` writers with AZPanel DE agent's shared lock before permitting
unattended policy publication.

## Deployment on the existing DE exit

**Before touching production:** record a Git revision of both repositories,
back up /root/antizapret/{parse.sh,config,download} and the active Knot RPZ
files, and confirm how /root/antizapret is installed. It may be a deployment
copy rather than a git clone; do not blindly replace local scripts with a
fresh repository copy. Get the two new files (parse.sh and rpz_allowlist.py)
from the **same reviewed commit**; preserve local customizations and diff
them before installing.

1. Ensure python3 and the new rpz_allowlist.py are installed under
   /root/antizapret. The updated parse.sh must be deployed together.
2. Create/extend config/exclude-deny-hosts.txt with the two domains above.
   Keep existing config/exclude-adblock-hosts.txt and config/include-hosts.txt
   unchanged; they govern different aspects of policy.
3. With the existing manual deny.rpz workaround still active, stage the build
   in a maintenance window or SSH session that will not be lost. Run
   python3 -m py_compile rpz_allowlist.py and
   python3 rpz_allowlist.py --help before invoking parse.sh.
4. Run ./parse.sh hosts. **Warning:** the existing parse.sh also invokes
   custom-parse.sh, which may reconnect WARP. Plan for this side effect.
5. Verify both the generated and deployed deny.rpz:
   grep -inE '(^|\*\.)?(ipify\.org|whatismyipaddress\.com)[[:space:]]' \
       /etc/knot-resolver/deny.rpz
   No matching blocking or passthru records should remain. Other deny
   records should still be present.
6. After the resolver has reloaded, test directly from DE:
   dig +short @127.1.1.1 api.ipify.org A
   dig +short @127.1.1.1 whatismyipaddress.com A
   Then from a connected client test its DNS plus actual HTTPS egress.
   Expected address for a domain included in selective policy: a Fake IP in
   the configured 198.18.0.0/15 range (configuration dependent), not 0.0.0.0.
7. Repeat ./parse.sh hosts and the tests. This is the persistence test:
   the denied rules must not return. If DNS differs or WARP stops working,
   restore backup RPZ and original scripts/config, clear the DNS cache, and
   check the resolver before retrying.

**Note:** This documentation change does not itself deploy any file or modify
RU, DE, router configuration, certificates, or active VPN sessions.

## Testing

    python3 -m unittest discover -s tests -v
    bash -n setup/root/antizapret/parse.sh

CI exercises valid/invalid entries, exact and wildcard rules, case and
trailing dot normalization, the passthru interaction, parent wildcard fail
closed, preservation of unrelated deny entries, and deterministic rebuilds.

The filter is generic policy machinery. For additional operator-required
domains add entries to exclude-deny-hosts.txt; do not edit generated RPZ.
